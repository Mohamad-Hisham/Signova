## Offline lifecycle and retention

Basil owns source/rights intake, immutable permitted raw originals, photo/video analysis, reviewed labels/boundaries, cleaning/quarantine, duplicate/parent/signer grouping, frozen splits, owner-specific recipes and directly usable releases. After handoff he maintains data defects, evaluation exposure, model lineage, approved acquisition and withdrawal; he does not become the application's database owner.

`raw/`, `interim/`, `processed/`, `features/` payloads are ignored except their README and marker. Keep restricted registers/release manifests in approved controlled storage; tracked metadata is public-safe only after content review. Requirement files and offline scripts are comment-only. `configs/`, `reports/`, `tests/` support reproducibility/audits without implementing tools or inventing results. See the [manifest guide](manifests/README.md) and [data governance policy](../docs/datasets/data-governance.md).
