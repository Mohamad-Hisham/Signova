# Model release and backend integration

Owners: Osama (alphabet), Bavly (words), Ali (runtime acceptance), Basil (lineage/rights), Hisham (scope/final acceptance), Adham (camera/UI verification). This describes future work; no release, weights, actual manifest or fake package is created here.

1. Freeze reviewed variety, supported labels, input/decision recipes, data/split/label/annotation versions and evaluated capture capabilities. Resolve representation, live-window and runtime questions before calling a model integration-ready.
2. Produce a trusted immutable inference artifact with exact ordered classes, deterministic preprocessing, runtime requirements, callable predictor/reset semantics, rejection/calibration/neutral policy, golden fixtures, reports, model card, integration instructions and SHA-256 checksums. [Model interface](../contracts/model-interface.md) is the complete checklist. Keep training-resume state separate from the runtime package.
3. Store binaries/restricted material in approved access-controlled external storage. Track safe metadata/immutable release reference/hashes in the relevant `artifacts/` area; template files here are not releases. Manifests declare each actual labels/policy/checksum filename rather than assuming both owners use the same layout.
4. Basil verifies rights/lineage, labels and independent evaluation/test exposure. Each model owner reports per-class support/metrics, acceptance coverage, defined negative false accepts, latency/memory/hardware and limitations; Bavly separately reports live-window and completion/neutral evidence. Targets are not achieved measurements.
5. Ali reproduces first inference in a clean target runtime with both inference packages compatible. Verify hashes, load once, warmup and run at least five permitted golden fixtures per model; compare intermediate tensors/scores with declared tolerances and accepted/rejected decisions. Missing/corrupt/wrong-map/shape/nonfinite/runtime cases fail safely and keep the mode unready.
6. Run the same approved source through Adham's sampler, actual JPEG decoding, owner recipe and dedicated adapter. Check orientation, aspect, sampling/gaps, no double normalization, exact class mapping, per-stream state isolation and safe timeout behavior. Shared weights do not imply shared trackers/buffers.
7. Exercise candidate→Confirm→canonical transcript, held/repeated signs, manual Pause/Start, explicit alphabet Space, edits, Clear during inference, disconnect/reconnect, offline removal and backend restart. Automatic completion stays disabled without evaluated neutral/release evidence and full joint acceptance. A trimmed-clip-only model can still block manual live mode.
8. Record compatibility matrix: model/data/split/recipe/labels/policy versions, artifact hash, backend/frontend/protocol references, hardware/runtime/provider, fixture/evaluation results, accepted scope, receiver names/date and rollback reference. Hisham accepts scope/evidence; no fabricated approval signatures.
9. A later rollout drains/ends sessions before a coordinated startup change; no hot-swapping weights or mappings under active transcripts. Warn users about RAM loss, activate compatible app/artifact versions together, verify readiness/golden checks, and retain a known-good package for rollback. No deployment infrastructure/actions are included in the scaffold.

If performance or compatibility fails, assign the first divergent stage to its owner. Do not reverse Arabic, adjust class order blindly, lower sample rate beneath training needs, reinterpret low score as neutral, or substitute a fake/random word. Mark the mode unavailable, keep manual fallback only when valid, or ask Hisham to narrow scope with evidence.
